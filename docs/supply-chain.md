# Supply chain security

## Implemented controls

- `requirements.lock`: exact application + development dependency versions, **complete**: it
  is compiled with `pip-compile --extra=dev` under the Python version CI uses (3.12) and must
  contain everything the test suite imports. Regenerate it in a `python:3.12` container, not on a
  developer's OS (a lock compiled on Windows once carried `colorama`). `scripts/reproduce.sh`
  installs from it alone, so a missing pin fails reproduction instead of hiding in CI.
- `requirements-runtime.lock`: exact runtime-only dependency versions used by Docker.
- `frontend/package-lock.json`: exact npm dependency graph installed with `npm ci`.
- multi-stage Docker build installs the runtime lock and the local wheel with `--no-deps`;
- both Docker stages pin the reviewed Python image manifest list by SHA-256 digest;
- every third-party GitHub Action is pinned to a resolved full commit SHA;
- CI runs `pip-audit`, `npm audit`, Gitleaks, package build, CycloneDX SBOM generation,
  SHA-256 artifact manifest, container build, Anchore scan and container SBOM;
- CI requests GitHub build provenance for wheel/SBOM/hash artifacts on `push` using the
  platform OIDC identity and artifact-attestation service; the OIDC/attestation permissions
  exist only in a minimal post-validation job that downloads the retained evidence;
- the scanned container image itself (not just the wheel/SBOM artifacts) is now pushed to
  GHCR by digest and attested on `push`: `container` builds and scans it, a separate
  `attest-container` job attests build provenance for that exact digest (it does not
  rebuild), and a third, independent `verify-container-provenance` job re-verifies that
  attestation from a fresh job/permission context using only the public image
  reference+digest and the repository identity — see "Container image provenance" below;
- `scripts/generate_artifact_manifest.py` rejects missing/out-of-repository inputs and
  hashes artifacts deterministically.

## Container image provenance (independent verification)

Before this change, the container job built and scanned an image that was never pushed or
attested — "the container image itself is not published or attested by this workflow" (see
below, now out of date for the reason it previously described). The gap closed here is
specifically the *independence* requested: provenance is not just generated by the same job
that built the image, it is verified by a separate job (and, outside CI, a separate
script) that trusts nothing from the build job except the public digest.

- `container` builds, scans (Grype, `only-fixed`/`high` gate) and pushes the image to
  `ghcr.io/<owner>/<repo>:<sha>`, capturing the resulting digest as a job output.
- `attest-container` (needs `container`) attests build provenance for that digest with
  `actions/attest-build-provenance`, using `subject-digest` rather than rebuilding —
  the attestation is bound to the artifact that was actually scanned.
- `verify-container-provenance` (needs both) runs
  `scripts/verify_image_provenance.py <ref>@<digest> --repo <owner>/<repo>`, which shells
  out to `gh attestation verify oci://...`. This is the independent check: a fresh job with
  its own minimal permissions (`attestations: read`, no `id-token`), re-deriving trust from
  the Sigstore-backed attestation rather than reusing anything the attesting job computed.
- The same script is meant to run again, by a human or a CD pipeline, immediately before
  promoting a digest to a production cluster — `make verify-provenance IMAGE_REF=ghcr.io/
  .../autonomous-red-teaming@sha256:...` — which is what actually "validates that the
  deployed image is exactly the one that passed CI," as opposed to validating it once in
  the same pipeline that produced it.
- This still does not publish or verify a *signature* (e.g. cosign keyless signing) on top
  of the attestation; `gh attestation verify` already checks the Sigstore transparency-log
  entry the attestation itself carries, so a separate cosign signature was judged redundant
  for now rather than omitted by oversight.

## Evidence boundary

The Python locks are exact but do not contain hashes because the local cross-platform
hash resolution did not complete. Artifact SHA-256 values protect produced evidence, not
dependency download provenance. The local Grype 0.119.0 scan is real evidence and fails the
configured `high` threshold with 50 High findings; the hosted CI run remains unexecuted.
The local Syft 1.52.0 CycloneDX image SBOM is retained under ignored `var/audit/`.

The base-image digest and Action commits were resolved on 2026-09-24. They are immutable
inputs but still require an explicit dependency-update process. Provenance generation and
independent verification are now both *configured* in the workflow (`container` ->
`attest-container` -> `verify-container-provenance`, and `scripts/verify_image_provenance.py`
for a deploy pipeline to re-run against the specific digest it is about to promote), but
this local, network-restricted development environment cannot mint or verify a
GitHub-hosted OIDC attestation — it can only be exercised by the hosted workflow. Before
promotion: execute the hosted workflow, confirm `verify-container-provenance` passed, run
`scripts/verify_image_provenance.py` again against the digest the deployment pipeline is
about to pull (not just the digest CI already checked), and retain the SBOM/scan/hash
artifacts. The Python locks do not yet include download hashes, and the new optional
adapters' dependencies (`boto3`, `hvac`, `alembic`, `sqlalchemy`) are not yet in
`requirements.lock`'s resolved graph for the same reason — regenerating it needs
`pip-compile` against a live PyPI, which this environment did not have when they were
added; CI installs `alembic`/`sqlalchemy` ad hoc until the lock is regenerated with network
access (see `.github/workflows/ci.yml`).

The previous Python 3.12.12/Bookworm base produced 16 Critical and 124 High matches. A
comparative migration to the current digest-pinned Python 3.13.16/Trixie base eliminated
all Critical matches and reduced High matches to 50. The remaining findings have not been
accepted or suppressed, so supply-chain promotion remains blocked.
